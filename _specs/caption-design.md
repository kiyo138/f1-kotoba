# 図版キャプションの意匠

対象: `build.py` の `render_flow_node`（img ノード）が出力する `<figure class="fig">` 配下の `<figcaption>`。
前提: 文言（図が何を言っているかの一文・40字程度）は別部署が確定させる。ここで定めるのは**見え方だけ**。

見本: `_specs/caption-design-sample.html`（キャプション有り／無しの両方を、本文の段落に挟んで並べたもの）

---

## 0. 何を解こうとしているか

`_specs/design-notes.md` 第7節に「390pxでは図中の文字が約5px相当になり読めない」とある。
その対策の(1)がこのキャプションである。つまりこの一文は**装飾ではなく、図の代替本文**である。
一方で、これが本文の段落と見分けがつかないと、読者は「図の説明」ではなく「地の文の続き」として読み、
図との対応が切れる。したがって設計上の要件は次の2つに尽きる。

- **本文より弱く**見えること（サイズ・色で階層を下げる）
- **図にぶら下がって**見えること（余白の比と、画像の縁と同じ色の縦罫で結ぶ）

---

## 1. 採用するDOM構造

### 1-A. キャプション有り

```html
      <figure class="fig">
        <a class="plate" href="f1-01-diagram.png">
          <img src="f1-01-diagram.png" width="1600" height="1173" loading="lazy" alt="…">
        </a>
        <figcaption><span class="cap-text">ハンドルを切っても前タイヤが滑り、車は外側へふくらんでいく。</span><span class="cap-hint">画像をタップすると大きく表示できます</span></figcaption>
      </figure>
```

### 1-B. キャプション無し（未記入の回）

```html
      <figure class="fig">
        <a class="plate" href="f1-01-parts.png">
          <img src="f1-01-parts.png" width="1600" height="953" loading="lazy" alt="…">
        </a>
        <figcaption><span class="cap-hint">画像をタップすると大きく表示できます</span></figcaption>
      </figure>
```

**1-B は現行の出力とまったく同一である。** キャプション未記入の回は build.py の出力を1文字も変えなくてよい。
`.cap-hint:only-child` 側でCSSが吸収する。

### 実装上、外してはいけない3点

1. **キャプション文は必ず `<span class="cap-text">` で包む。** 素のテキストノードにしない。
   CSSが「案内文だけの状態」を `.cap-hint:only-child` で判定しており、
   `:only-child` は**要素**しか数えないため、素のテキストノードだと有りと無しを区別できない。
2. **キャプションが未記入のときは `<span class="cap-text"></span>` を出さない。** 空の span を残すと
   `:only-child` が外れ、案内文の行頭に 8px の不要な字下げが残る。span ごと省略すること。
3. **`</span><span class="cap-hint">` の間に改行・空白を入れない。** 語間は CSS の
   `margin-inline-start:.5em` で作る。ソース中の改行が空白1個として入ると、間隔が二重になる。

`<figcaption>` は `<a class="plate">` の**外**に置く（現行どおり）。中に入れると押せる領域が
キャプションまで広がり、「どこを押すと拡大するのか」が曖昧になる。

ヒーロー図版（`.fig-hero`）は現行どおり `figcaption` を持たない。この意匠は本文中の図版だけに掛かる。

## 2. CSS

### 2-1. 変更（before / after）

`build.py` の CSS ブロック「--- 7. 図版 ---」内、`figcaption` と `.cap-hint` を差し替える。
セレクタ名は現行のまま（`figcaption` / `.cap-hint`）。**新しい色トークンは足していない。**

**before**

```css
figcaption{
  margin-top:12px;
  font-size:1rem;             /* 16px */
  line-height:1.75;
  color:var(--sub);
}
.cap-hint{
  display:block;
  margin-top:4px;
  font-size:.9375rem;
  color:var(--sub);
}
.cap-hint::before{ content:"⤢ "; }
```

**after**

```css
/* 図の説明文＋拡大の案内。
   図が読めない画面のための代替本文なので、本文より一段弱く、かつ図にぶら下げて見せる。
   縦罫は画像の縁 --plate-rim と同色。画像の枠が下へ続いているように見せるため。 */
figcaption{
  margin-top:12px;
  max-width:34rem;                /* 544px。広い画面で1行32字前後に抑える */
  padding-inline-start:12px;
  border-inline-start:2px solid var(--plate-rim);
  font-size:1rem;                 /* 16px。本文は17/18pxなので必ず一段小さい */
  line-height:1.75;               /* 本文1.9より詰める。図の一部としてひと塊に見せる */
  color:var(--sub);               /* #5A5D64 / 暗色時 #A8ABB1 */
  text-align:start;
  text-wrap:balance;              /* 折り返した行の長さを揃える。非対応環境では無視される */
}
@media (min-width:600px){
  figcaption{ margin-top:16px; }
}

/* 案内文はキャプションと同じ段落の中に続けて置く（別行に立てない） */
.cap-hint{
  margin-inline-start:.5em;       /* キャプション文との間 8px */
  font-size:.9375rem;             /* 15px */
}
.cap-hint::before{ content:"⤢ "; }
.cap-hint:only-child{ margin-inline-start:0; }   /* キャプション未記入の回 */
```

### 2-2. 何を消したか、なぜか

| 消した宣言 | 理由 |
|---|---|
| `.cap-hint{ display:block }` | 案内文を独立行に立てるのをやめ、キャプション文に続けるため（第3節） |
| `.cap-hint{ margin-top:4px }` | 独立ブロックでなくなったので不要。行間は figcaption の `line-height` が持つ |
| `.cap-hint{ color:var(--sub) }` | 親 `figcaption` から継承する。同じ値の二重指定を残さない |

### 2-3. 触らないもの

`.fig`（`margin:36px auto` / ≥600px で `44px`）、`.plate`、`.fig-hero`、
カラートークン、フォントスタック、本文サイズ ── いずれも変更しない。
この意匠は `figcaption` と `.cap-hint` の2セレクタで閉じている。

## 3. 案内文は「統合する」

**結論: 案内文「画像をタップすると大きく表示できます」は残す。ただし独立行をやめ、キャプション文と同じ
段落の中に、⤢ 記号を挟んで続ける。**

### 残す理由

`design-notes.md` 第7節が挙げる3つの対策のうち、(2)「画像をPNGへのリンクにする」は、
(3)「案内の一文」が無いと**存在に気づけない**。リンクであることを示す視覚的手がかりが他に無い
（下線も色替えもしていない。図の地と本文の地が同色なので、装飾を足せないという意匠上の制約がある）。
高齢の読者ほど「画像が押せる」という前提を持たない。案内文はこの意匠でいちばん実用に効く一文であり、
削るとリンクが死ぬ。よって削除も、視認できない大きさへの縮小もしない。

### それでも独立行をやめる理由

キャプションが入ると、図の下に「補助文字色の短い文章」が2ブロック縦に並ぶ。
しかも下側は毎回・全図で同一の定型文である。390pxでは
「キャプション2行 ＋ 4pxの隙間 ＋ 案内1行」となり、**定型文がキャプションと同格の主張を持ってしまう。**
同じ塊の中に流し込めば、ラグ（右端の凹凸）が1つになり、視線の止まる場所が1つ減る。

### 「淡くする」「もっと小さくする」を採らなかった理由

- **淡くできない。** 補助文字 `--sub` はこの配色で使える最も薄い文字色（地に対し6.05:1）。
  これ以上薄くすると本文サイズのAA基準 4.5:1 を割る。新しい灰色を足すのは配色を増やすことになり禁じ手。
- **もっと小さくしない。** 15px は既存の下限（回数・ラベル類）。高齢の読者が主対象である以上、
  実用上意味のある一文を14px以下に落とさない。

### 区別の手がかり（色に頼らない）

キャプション文と案内文の見分けは、**⤢ 記号（形）** と **16px / 15px（大きさ）** の2つで付ける。
色は両方 `--sub` のままで、色差には頼っていない。

### 文言についての申し送り（別部署の判断事項）

現行の17字のままで成立する。ただし案内文が行末に収まらず次行へ送られる回数を減らしたいなら、
「タップで拡大表示」（8字）程度への短縮が効く。**これは意匠側の要求ではなく、選択肢の提示である。**
文言を変える場合も CSS は変わらない（`CAP_HINT_TEXT` の差し替えだけで済む）。

## 4. 390px と 1280px でのふるまい（実数値）

### 390px（スマホ・最優先）

| 項目 | 値 |
|---|---|
| 画面左右余白 `--pad` | 16px（既存） |
| 図版・キャプションの外枠幅 | 358px |
| figcaption 上マージン | 12px |
| 縦罫 + 字下げ | 2px + 12px = 左14px |
| キャプション文の実効行幅 | 344px |
| キャプション文字サイズ | 16px（本文17pxより1px小） |
| 行間 | 1.75 → 行の高さ 28px（本文は1.9） |
| 1行に入る和文 | 約20字（字間.03em込み） |
| 40字のキャプション | **2行**（`text-wrap:balance` で20字前後ずつに割れる想定） |
| 案内文 | 15px。上の行に入りきらなければ次行へ送られる |
| キャプション有りの塊の高さ | 約84px（28px × 3行） |
| 図の下端から次の本文まで | 12 + 84 + 36 = 約132px |
| キャプション無しの塊の高さ | 28px（1行）。図の下端から次の本文まで 12 + 28 + 36 = 76px |

- 図とキャプションの間 **12px** に対し、キャプションと次の本文の間 **36px**。
  **1:3 の比**で、キャプションがどちらに属するかが余白だけで読める。
- `text-align:start`（左揃え）。中央揃えにしない。折り返したとき各行の頭が揃わず、
  和文2行以上では行頭を探す動きが生じるため。
- `line-break:strict`（body から継承）が効くので、小書きかな・約物の行頭禁則は本文と同じ厳しさになる。

### 1280px（PC）

| 項目 | 値 |
|---|---|
| `.wrap` 内容幅 | 872px（920px − 左右24px）、画面中央 |
| 図版の表示幅 | 872px |
| figcaption 上マージン | 16px |
| figcaption の最大幅 | 544px（`34rem`）。図の**左端に揃えて**左寄せ |
| キャプション文の実効行幅 | 530px |
| 1行に入る和文 | 約32字 |
| 40字のキャプション | **2行**（20字前後ずつ） |
| 図の下端から次の本文まで | 16 + 約56 + 44 = 約116px |

- **872px 幅いっぱいに流さない理由。** 16px の文字が872pxに流れると1行53字になり、
  `design-notes.md` 第3節が本文に定めた上限（35〜36字）を大きく超える。
  補助文字色の小さい文字ではさらに戻りづらい。544px に切って1行32字に抑える。
- **中央寄せにせず左寄せにする理由。** 図の左端 = キャプションの左端 が揃うことで、
  キャプションがその図に属することが一目で分かる。1280pxでは図の左端は本文段落の左端より
  104px 外側にあり、この段差自体が「本文ではない」という合図になる。
- 右側に328pxの余白が残るが、これは間延びではなく**行長の制御**である。

### 600px 境目

`--pad` が 24px に、本文が18pxになるが、キャプションは16pxのまま（`design-notes.md` 第3節の
「キャプション・予告は16px固定」に従う）。本文との差が1px→2pxに開き、階層はむしろ明確になる。

## 5. アクセシビリティ上の確認事項

- キャプション16px・案内文15px。いずれも `rem` 指定で、ブラウザの文字サイズ設定に追随する。
  `white-space:nowrap` は**使っていない**（大きな文字サイズ設定時に横スクロールを生ませないため）。
- 文字色は `--sub`。明色 6.05:1、暗色 8.0:1。どちらもAA基準を満たす（`design-notes.md` 第1節）。
- 色だけで区別している要素は無い。キャプションと案内文は記号（⤢）と大きさで分けている。
- キャプションと `alt` の内容は重複しうる。読み上げ環境では両方読まれる。
  これは現状の `alt` 方針（第7節「altは図が示している関係を文章で書く」）を変えないという判断で、
  重複を許容している。気になる場合は director の判断で `alt` を短くする余地がある。
- `.cap-hint::before` の ⤢ は擬似要素の content なので、読み上げ環境によっては
  「上向き矢印」等と読まれる可能性がある。現行からの継続であり、本件では変更していない。

## 7. 未確認事項

筆者はブラウザで表示を確認する手段を持たない。以下は**計算上の値であり、実機で見ていない。**

- 390pxでの「1行約20字」「40字が2行」は、16px + 字間.03em からの算術であり、実測ではない。
  実際の書体（Hiragino Sans / Yu Gothic Medium）の字幅で1〜2字ずれる可能性がある。
- `text-wrap:balance` の効き。未対応ブラウザでは単に無視される（崩れはしない）が、
  対応ブラウザでの割れ方は目視で確認してほしい。3行になる場合（キャプション2行＋案内1行）に
  不自然な短行が出るなら、この1宣言を削れば従来どおりの折り返しに戻る。
- 縦罫（`border-inline-start:2px solid var(--plate-rim)`）の見え方。暗色時、
  `.plate` 側の縁は `filter:brightness(.90)` を通っているのに対し、キャプションの縦罫は素の
  `#4A5058` で出るため、わずかに明るく見えるはず。実機で気になるなら
  縦罫の色を `var(--rule)` に落とすか、`padding-inline-start` ごと外して余白だけで結ぶ手もある
  （`border-inline-start` と `padding-inline-start` の2行を削るだけで戻せるようにしてある）。
