# F1のことば、あいうえお ── 意匠の指針

見本: `_specs/design-article.html`（第3回・実データ）／ `_specs/design-index.html`（3回分の索引）
CSSは両ファイルの `<style>` に直書き。**共通スタイルのブロックは両ファイルで完全に同一**なので、
ビルドスクリプト側では1箇所に持って各HTMLへ流し込むこと。外部CSS・外部フォント・JSは無し。

---

## 1. カラートークン

| 変数 | 明色 | 暗色 | 用途 |
|---|---|---|---|
| `--bg` | `#F6F5F2` | `#15171A` | 地。図版PNGの地と同一色 |
| `--ink` | `#191B1F` | `#E9E7E2` | 本文・見出し |
| `--sub` | `#5A5D64` | `#A8ABB1` | 補助文字（キャプション、予告、回数） |
| `--accent` | `#D4342A` | `#F2564A` | 罫・印・大きな文字 |
| `--accent-text` | `#B32A21` | `#F2564A` | **小さい文字用の強調色** |
| `--rule` | `#DDDAD3` | `#2E3238` | 細罫・画像の縁 |
| `--rule-strong` | `#C6C2B9` | `#3D424A` | 押せる要素の縁 |
| `--panel` | `#EDEBE5` | `#1D2126` | 箇条書きの面 |
| `--card` | `#FCFBF9` | `#1B1E23` | カード・ボタンの面 |
| `--plate-rim` | `#DDDAD3` | `#4A5058` | 画像の縁 |

**`#D4342A` を小さい文字に使ってはいけない。** 地色 `#F6F5F2` に対して 4.46:1 で、
本文サイズのAA基準 4.5:1 をわずかに割る。小さい文字には `--accent-text`（5.89:1）を使う。
`#D4342A` は罫・丸印・大きな見出し文字（3:1で足りる用途）に限る。

補助文字 `#5A5D64` は 6.05:1、本文 `#191B1F` は約16:1。いずれも問題ない。

**回ごとの配色ローテーション（ペトロールグリーン／ライムイエロー等）はページ側に持ち込まない。**
理由は2つ。(1) ライムイエローやゴールドは `#F6F5F2` の上でコントラストを確保できない。
(2) 回ごとの表情はヒーロー画像が担い、ページ側は連載として一貫した1色（赤）で通したほうが、
索引に20枚並べたときに秩序が保てる。

## 2. フォントスタック

```css
font-family:
  system-ui, -apple-system,
  "Hiragino Sans", "Hiragino Kaku Gothic ProN",
  "Noto Sans JP",
  "Yu Gothic Medium", "游ゴシック Medium", "Yu Gothic", YuGothic,
  "Meiryo", sans-serif;
```

- 先頭の `system-ui` はLatinを各OSの標準UI書体（SF Pro / Segoe UI / Roboto）で拾う。
  和文グリフを持たないため、かな漢字は自動で後続へ落ちる。「第3回」「2026年」「DRS」の数字・英字が整う。
- Windowsは `Yu Gothic Medium` を `Yu Gothic` より先に置く。游ゴシックのRegularは細すぎて
  本文で読みづらいため、Mediumウェイトの実体を通常書体として拾わせる。
- 太字は `font-weight:700` のみ。中間ウェイトは環境差が大きいので使わない。

## 3. 字送り・行間・行長

| 項目 | 狭い画面 | ≥600px |
|---|---|---|
| 本文 | `1.0625rem`（17px） | `1.125rem`（18px） |
| 行間 | 1.9 | 1.9 |
| 字間 | `.03em` | `.03em` |
| h2 | 21px | 23px |
| 記事タイトル | 30px | 38px |
| キャプション・予告 | 16px | 16px |
| 回数・ラベル類 | 15px | 15px |

- サイズはすべて `rem`。ブラウザの文字サイズ設定を尊重する。`px` 固定にしないこと。
- 本文1行の最大幅 `--measure: 41.5rem`（664px）。18pxで約35〜36文字。日本語で目が迷わない上限。
- 見出しにのみ `font-feature-settings:"palt" 1` を当て、「、」「（）」のアキを詰める。本文には当てない。
- `line-break:strict` で禁則を厳しめに（小書きかなを行頭に置かない）。
- 原稿txtの行内改行は**組版都合**なので `<br>` にせず結合する。空行で `<p>` を切る。
  索引ページのリード文だけは意図的に `<br>` を1つ入れている（2文を見せるため）。

## 4. 余白

4pxを刻みとする。実際に使うのは 8 / 10 / 12 / 16 / 20 / 24 / 36 / 44 / 48 / 56 / 64。

- 段落間 `1.55em`（本文サイズ連動）
- h2 上 48px（≥600pxで64px）／下 18px ── 節の切れ目が段落間の3倍以上になり、階層が一目で立つ
- 図版の上下 36px（≥600pxで44px）
- 画面左右 16px（≥600pxで24px）── 狭い画面では図版の実効幅を稼ぐため16pxに抑えている

## 5. レイアウトとブレークポイント

ブレークポイントは2つだけ。`600px` と `960px`。

```
.wrap   max-width 920px  ← ページの外枠
.col    max-width 664px  ← 文字が入るもの全部（ヘッダ・タイトル・本文・予告・ナビ・フッタ）
.prose > figure  max-width 920px  ← 図版だけが本文桁からはみ出す
```

- 本文桁（664px）から図版だけを920pxへ広げる。**図版PNGの中の文字を1pxでも大きく見せるため。**
- ヘッダ・タイトル・予告・ナビ・フッタは図版ではなく本文桁に揃える。文字の左端が全部そろう。
- 索引ページも同じ規則。見出し・リードは664px、行見出しとカード格子だけが920pxへ広がる。
  記事ページの「文字は664、図版は920」と同じ関係を、索引でも崩さない。
- 索引カード: 1カラム → `600px` で2カラム → `960px` で3カラム。

## 6. 見出し・箇条書き・かなタイル

- **h2 は「文字 + その下に赤い短い罫（72×3px）」。** 図版PNGが既に
  「タイトル＋赤い下線」で作られているので、ページの見出しと図の見出しが同じ作法になる。
- **箇条書き**は `--panel` の面に載せ、`・`の代わりに7pxの赤い丸を字下げ位置に置く。
  流れる本文の中で拾い読みできるようにするため。第3回本文には箇条書きが無いので、
  見本HTMLの下部「意匠見本」欄に第1回の実物で体裁を示してある。
- **かなタイル**（赤い角丸枠に かな1文字）は記事タイトル・記事末ナビ・索引カードで共通の部品。
  五十音順という連載の背骨を、どのページでも同じ形で見せる。

## 7. 図版の扱い ── 本設計でいちばん重要な点

図版PNGは1600px幅の中に20〜30pxの文字が入っている。
**390pxの画面では図版の実効幅は358px、図中の文字は約5px相当になり、読めない。**
これは縮小の副作用ではなく、この意匠が解かねばならない一番の課題である。対策は3つ。

1. **`<figcaption>` に、図が言っていることを文章で書く。**
   図が読めなくても本文の理解が途切れないようにする。文言は図の中の説明文をそのまま起こす（新たに書かない）。
2. **画像をPNGへのリンクにする。** `<a class="plate" href="f1-03-wing.png"><img ...></a>`
   タップすると原寸PNGが開き、端末のピンチ操作で拡大できる。JSは不要。
3. **「画像をタップすると大きく表示できます」の一文を必ず添える。** リンクだと気づけないため。

その他:
- `width` / `height` 属性を必ず出力する（読み込み中のガタつき防止）。
  **見本の値は暫定。** ビルド時にPILで実寸を読んで書き出すこと。
  ヒーローは1600×900で確定。`f1-03-wing.png` は 1600×780、`f1-03-mode.png` は 1600×770 と仮置きしている。
- ヒーローは `loading` 指定なし（即時）、本文中の図版は `loading="lazy"`。
- `alt` は「図：〜」で始め、図が示している関係を文章で書く。装飾ではないので空にしない。
- 画像の枠は**細罫1本だけ**。図版の地が `#F6F5F2` で本文の地と同色なので、
  重い枠や影を付けると逆に浮く。地が地に溶け、輪郭だけが残る状態が正しい。

## 8. 記事末ナビ（片方が欠ける場合）

- 上段に「← 索引へ」を横幅いっぱいのボタン（高さ56px）で1本。
- 下段に「前の回」「次の回」。狭い画面は縦積み、600px以上で左右2枠。
- **行ける側**: `--card` の面 + `--rule-strong` の実線枠 + 矢印（← / →）+ 回数・かなタイル・語。
- **欠けている側**: 面なし + 破線の細罫 + 補助文字色 + 矢印なし。文言で状態を伝える。
  - 前が無い（第1回）→「ここが連載のはじまりです。」
  - 次が無い（最新回）→「これが最新回です。毎週ひとつ増えます。」
- 枠を消さずに残すのは、**左右のどちらが欠けているのかを見せるため。**
  片方を消すと、残った1枠がどちらの向きなのか読み取りに一拍かかる。
- 方向は「位置」「矢印」「文言」の3つで示す。色には頼っていない。

見本HTMLの下部「意匠見本」欄に、欠けなし／前が欠け／次が欠け の3パターンを並べてある。

## 9. 索引ページ

- カード = ヒーロー画像（16:9）+ 回数 + かなタイル + 語 + 一言。カード全体が1つのリンク。
- **一言は、その回の最初のh2をそのまま使う。**（第1回「曲がりたいのに、曲がってくれない」など）
  新しく文章を書かずに済み、ビルドスクリプトが本文txtから機械的に抜ける。
- **並びは第1回からの昇順で固定。** 五十音順そのものが連載の構造なので、新着順にしない。
  代わりに最新回へ「最新」の札を付ける（色だけでなく文字で示す）。
- 20回を超えることを見越して、**「あ行」「か行」…の行見出しで束ねる。**
  今は「あ行」1つだけだが、増えても構造は変わらない。ビルド側は かな→行 の対応表を持てばよい。
- カードの地は `--card`、サムネイルの枠内の地は `#F6F5F2`。
  画像の地と同色なので画像とカードの継ぎ目が出ない。

## 10. ダークモード ── 採用する

`prefers-color-scheme: dark` で切り替える。**採用の理由**は、読者の大半がチャットのリンクから
スマホで来るためで、夜間にOSがダークのまま真っ白な長文を開くのは実害があるから。
トークン差し替えだけで済むので保守の負担も小さい。

明るい図版PNGが浮かないための手当て（3点セット）:

1. 地を純黒にせず `#15171A` にする。地と図版の明度差を必要以上に開かせない。
2. 画像の枠 `--plate-rim` を暗色時だけ `#4A5058`（中間明度）に上げ、
   明るい版面を「額装された図」として縁取る。枠が無いと白い板が宙に浮く。
3. `filter: brightness(.90)` を画像の枠ごと当て、明るさだけ落とす。
   色相・彩度は動かさないので、図中の赤・青は本文の強調色と食い違わない。

暗色時は強調色を `#F2564A` に上げる（`#15171A` に対して5.3:1）。
`#D4342A` のままだと 3.7:1 で小さい文字に使えない。
「最新」札の文字色も暗色時は `#15171A` に反転させる（赤地に白は暗色時 3.4:1 で不足するため）。

**未確認:** 筆者はブラウザ表示を確認する手段を持たない。
暗色時の図版の見え方（`brightness(.90)` の効き具合、縁取りの明度）は、
実装担当が実機で必ず目視して調整すること。強すぎる/弱すぎる場合は
`--img-filter` と `--plate-rim` の2つだけ触れば済むようにしてある。

## 11. 実装担当への申し送り

1. **画像パス。** 見本は `../ウイング/f1-03-hero.png` で繋いでいる。
   本番はPNGを各回フォルダにコピーするので `f1-03-hero.png` になる。差はここだけ。
   リンク先（`a.plate` の `href`）も同じパスに揃えること。
2. **`width`/`height` 属性は実寸を出力する。** 見本の値は暫定（第7節参照）。
3. **原稿txtの改行を `<br>` にしない。** 空行で段落を切り、段落内の改行は結合する。
4. **`・` 始まりの行は `<ul>/<li>` にする。** 連続する `・` 行を1つの `ul` にまとめること。
5. **`■` 行が `<h2>`。** 冒頭の `━━━` 囲みヘッダと末尾の `────` 囲み予告は、
   それぞれタイトル部・`.next-up` に振り分ける。txtの罫線文字はHTMLに出さない。
6. **共通スタイルは1本で管理する。** 2ファイルの `<style>` 前半は同一。
   索引固有のCSSは末尾の「索引ページ固有」以降だけ。
7. **`.spec-zone` 以下は見本用の装置。** 本番テンプレートには含めない。
8. `<title>` は `第N回「か」語｜F1のことば、あいうえお`、
   `<meta name="description">` は本文冒頭から1〜2文。OGP画像を出すならヒーローPNGを指定。
9. JSは使っていない。今後も画像の拡大・ナビ・索引のためにJSを足す必要はない。
